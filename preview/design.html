设计依据 参考的是已经收敛的评审类界面模式

  1. 两栏“diff + 批注卡”：左侧代码/改动，右侧固定放批注卡，每张卡由严重度徽标 + 正文 + 跳回 diff 的链接组成。方案 A 的两栏（改动 / 风险）就是把这条规则搬到卡片内部。来源
  2. 上下文与结论分离：GitHub 把 overview / comments / merge status / alerts 做成可停靠面板，避免评审时丢失上下文。对应到卡片：顶部固定“判定 + 一句话结论”，细节折叠。来源
  3. 文件列表带比例条：changed-files 树的成熟做法是每文件 +/− 加一条占比条，让“改动集中在哪”一眼可见。来源

对应到现有字段：verdict → 顶部判定条；summary / intent → 结论区；focus → 左栏文件行；risks → 右栏严重度列表；questions → 折叠区；recommend → 底部建议。
